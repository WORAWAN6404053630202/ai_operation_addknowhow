## ระบบนี้คืออะไร?

### ชื่อ: น้องสุดยอด (Restbiz)

**หน้าที่:**
- 🤖 บอท AI ที่ช่วยเจ้าของร้านอาหาร
- 📋 ตอบคำถามเรื่องกฎหมายและการดำเนินธุรกิจ
- 🎯 ให้คำแนะนำขั้นตอนการขอใบอนุญาต, ภาษี, ประกันสังคม, QR Payment ฯลฯ

**หลักการพื้นฐาน:**
```
ตอบจากข้อมูล = ✅ ดี
คาดเดา / แต่งเติม = ❌ ผิด
```

บอทจะตอบเฉพาะสิ่งที่มีในฐานข้อมูลจากหน่วยงานต่างๆ

## ภาพรวมการทำงาน

### ขั้นตอน 3 ระดับ

```
┌─────────────────────────────────────────────────────────────┐
│ 1️⃣  USER พิมพ์ข้อความ                                        │
│     เช่น "ขอใบอนุญาตจำหน่ายสุรา"                            │
└────────────────┬────────────────────────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────────────────────────┐
│ 2️⃣  SYSTEM วิเคราะห์คำถาม + ค้นข้อมูล                        │
│     ├─ ทักทาย → ไม่ค้นข้อมูล                               │
│     ├─ ถาม กฎหมาย/ใบอนุญาต → ค้นข้อมูล                   │
│     └─ ขอแบบละเอียด → เปลี่ยนโหมด                           │
└────────────────┬────────────────────────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────────────────────────┐
│ 3️⃣  SYSTEM ตอบคำถาม                                         │
│     ├─ ขั้นตอน                                              │
│     ├─ เอกสารที่ต้องใช้                                     │
│     ├─ ค่าธรรมเนียม                                         │
│     └─ ลิงก์สำหรับดาวน์โหลด / เสื่อมสูง                      │
└─────────────────────────────────────────────────────────────┘
```

## โครงสร้างระบบ

### ส่วนประกอบหลัก (Components)

```
┌─ FastAPI Server (Web Server) ──────────────────────────────┐
│  ┌──────────────────────────────────────────────────────┐ │
│  │ 📱 Router (API Endpoints) ← ตัวรับและส่งข้อมูล       │ │
│  │   - /api/operation/greeting  → สร้าง session       │ │
│  │   - /api/operation/chat      → รับข้อความ & ตอบ    │ │
│  │   - /api/operation/sessions  → ดูทั้งหมด            │ │
│  └──────────────┬───────────────────────────────────────┘ │
│                 │                                          │
│  ┌──────────────▼───────────────────────────────────────┐ │
│  │ 🧠 PersonaSupervisor (สมองของระบบ) ← ตัดสินใจ      │ │
│  │   - สำคัญมาก! ตัดสินใจว่าจะทำอะไร                │ │
│  │   - เลือกใช้ Practical หรือ Academic persona       │ │
│  │   - จัดการ state & context                         │ │
│  └──────────────┬───────────────────────────────────────┘ │
│                 │                                          │
│    ┌────────────┴────────────┬──────────────┐             │
│    │                         │              │             │
│    ▼                         ▼              ▼             │
│  ┌─────────────┐         ┌──────────┐  ┌───────────┐    │
│  │ Practical   │         │Academic  │  │ Retriever │    │
│  │ Persona     │         │Persona   │  │ (ค้นข้อมูล)   │
│  │ (โหมดปกติ) │         │(เชิงลึก) │  └───────────┘    │
│  └─────────────┘         └──────────┘                   │
│                                                          │
│  ┌──────────────────────────────────────────────────┐ │
│  │ 💾 StateManager (จำคำสนทนา & ข้อมูล)           │ │
│  │    บันทึกไฟล์ JSON พื้นฐานข้อมูล state           │ │
│  └──────────────────────────────────────────────────┘ │

│  ┌──────────────────────────────────────────────────┐ │

│  └──────────────────────────────────────────────────┘ │
│                                                          │
└────────────────────────────────────────────────────────┘

┌─ Databases & Storage ──────────────────────────────────────┐
│  ├─ Chroma DB ← ฐานข้อมูลเวกเตอร์ (สำหรับค้นหา)        │
│  ├─ File System ← เก็บ session state (JSON)              │
│  └─ Cache ← เก็บคำตอบอันใหม่เพื่อตอบเร็ว                │
└────────────────────────────────────────────────────────────┘

┌─ External Services ────────────────────────────────────────┐
│  └─ OpenRouter API ← เรียก Claude/GPT สำหรับ AI reasoning │
└────────────────────────────────────────────────────────────┘
```

## Flow ตามกรณี

### 📝 กรณีที่ 1: User ทักทาย

```
┌──────────────────────────────────────────────────────────────┐
│ User ทำการพิมพ์:                                              │
│ • "สวัสดี"                                                    │
│ • "หวัดดี"                                                    │
│ • "สวัสดีครับ"                                                │
│ • (ข้อความว่าง - เปิด app ครั้งแรก)                           │
└─────────────────────┬──────────────────────────────────────┘
                      │
        ┌─────────────▼─────────────┐
        │ System ตรวจสอบว่า:       │
        │ • เป็นคำทักทายหรือไม่?    │
        │ • ผู้ใช้เคยทักทายแล้วหรือ?│
        └─────────────┬─────────────┘
                      │
        ┌─────────────▼──────────────────────┐
        │ ตรวจพบ: เป็นคำทักทาย                │
        │ ไม่ต้องค้นข้อมูลใดๆ                │
        │ สร้าง session ใหม่ (unique ID)    │
        └─────────────┬──────────────────────┘
                      │
        ┌─────────────▼──────────────────────────────────┐
        │ Bot ตอบ:                                       │
        │ "สวัสดีครับ! มีอะไรให้ช่วยไหมครับ 😊"         │
        │                                                │
        │ 📋 แสดงเมนู 5 หัวข้อ (สุ่มจากฐานข้อมูล):     │
        │ 1) ขอใบอนุญาตจัดตั้งสถานที่จำหน่ายอาหาร       │
        │ 2) วิธีการลงทะเบียน QR-Payment API             │
        │ 3) ประกันสังคมพนักงาน                         │
        │ 4) ภาษีมูลค่าเพิ่ม (VAT)                       │
        │ 5) ลงทะเบียนพาณิชย์                           │
        │                                                │
        │ ✅ Session สร้างเสร็จ → เก็บในไฟล์            │
        │ ✅ บันทึก log: greeting displayed              │
        └────────────────────────────────────────────────┘

การเก็บข้อมูล (State):
├─ session_id: "abc12345"
├─ persona_id: "practical"  (โหมดปกติ)
├─ messages: [
│    {role: "assistant", content: "สวัสดีครับ!..."}
│  ]
├─ context: {
│    did_greet: true,
│    last_menu_topics: [หัวข้อ 5 ชิ้น]
│    round: 1
│  }
└─ created_at: 2026-04-21 10:30:00
```

### 🔎 กรณีที่ 3: User ถามคำถามหลายเรื่อง (Broad Question)

```
┌──────────────────────────────────────────────────────────────┐
│ User ถาม:                                                     │
│ • "อยากเปิดร้านเบเกอรี่ต้องทำอะไรบ้าง"                       │

        │ System ตรวจสอบ:               │
        │ เป็นคำถาม broad_question?     │
        │ (ครอบคลุมหลายหัวข้อ)          │
        │ → ใช่ detected!                │
        └─────────────┬──────────────────┘
                      │
        ┌─────────────▼──────────────────────────────────────┐
        │ ค้นข้อมูล (2 รอบ):                                │
        │                                                   │
        │ 🔍 รอบ 1: ค้นหาตามคำถาม user                    │
        │   query: "เปิดร้านเบเกอรี่"                      │
        │   → ได้เอกสาร 10 ชิ้น                            │
        │                                                   │

        └─────────────┬──────────────────────────────────────┘
                      │
        ┌─────────────▼──────────────────────────────────────┐
        │ Bot ตอบแบบภาพรวม (สตรีมมิ่ง):                    │

### 📚 ที่มาของข้อมูล (Data Source)

```
Google Sheets (Thai Government Data)
    ↓
DataLoader (code/service/data_loader.py)
    ├─ อ่าน CSV export
    ├─ Clean header
    ├─ Validate schema
    ├─ Convert to Document format
    ↓
LocalVectorStoreManager (code/service/local_vector_store.py)
    ├─ Load HuggingFace Embeddings (intfloat/multilingual-e5-large)
    ├─ Convert text → vector (1024 dimension)
    ├─ Store in Chroma DB
    ↓
Chroma Vector Database
    ├─ Persistent storage: local_chroma_v3/
    ├─ Similarity search: retrieve top-K docs
    ↓
Retriever (used by Supervisor/Persona)
    └─ return: List[Document] with metadata
```

```
User Input (Query)
    ↓
┌─────────────────────────────────┐
│ Step 1: Expand Query            │

│ Step 2: Encode to Vector        │

│ ใช้ multilingual-e5-large       │
│ Output: [0.23, -0.15, ..., 0.7] │

└─────────────┬───────────────────┘
              ↓

│ Step 3: Search Vectors          │

│                                 │

              ↓
┌─────────────────────────────────┐
│ Step 4: Filter & Re-rank        │
│                                 │
│ ├─ ตัดค่า similarity < 0.6     │
│ ├─ ลบ duplicates                │
│ ├─ Sort by score               │
│ └─ Keep top N (depend on mode) │
│    - Practical: 6 docs          │
│    - Academic: 12 docs          │

              ↓

    │   ├─ topic: "QR Payment"

### ⚙️ State Machine (FSM)

```
[PRACTICAL Mode]
                         
S_IDLE
  ├─ greeting? → show menu
  ├─ legal_question? → retrieve → ask slots → answer
  ├─ want_academic? → switch to academic
  └─ smalltalk? → brief reply

[ACADEMIC Mode]

S_IDLE
  └─ start_intake? → S_ACAD_INTAKE

S_ACAD_INTAKE
  ├─ ask slots (required)
  └─ → S_ACAD_INTAKE_SLOTS

S_ACAD_INTAKE_SLOTS
  ├─ user fills slots
  └─ all done? → S_ACAD_ANSWER

S_ACAD_ANSWER
  ├─ ask sections
  └─ → S_ACAD_AWAITING_SECTIONS

S_ACAD_AWAITING_SECTIONS
  ├─ user chooses sections
  └─ → S_ACAD_ANSWERING

S_ACAD_ANSWERING
  ├─ detailed answer
  └─ user satisfied? → S_AUTO_RETURN

S_AUTO_RETURN
  └─ return to practical mode automatically
```

## Error Handling

### ❌ ประเภท Error

```
1️⃣ Graceful (User เห็น):
   ├─ "ขอโทษครับ ไม่เข้าใจ"
   ├─ "ไม่มีข้อมูลเรื่องนี้"
   ├─ "กรุณา Type ใหม่นะครับ"
   └─ "สนทนามากเกินไปแล้ว"

2️⃣ Silent (Log only):
   ├─ Retrieval returned 0 docs → use fallback prompt
   ├─ LLM timeout → return cached response
   ├─ Lock timeout → log warning, proceed anyway
   └─ Cache miss → compute & store

3️⃣ Critical (Crash & Log):
   ├─ Config error (API key missing)
   ├─ Database connection failed
   ├─ Vector embedding model load failed
   └─ File system permission error

Recovery:
├─ Health check endpoint (/api/monitoring/health)
├─ Service status dashboard
├─ Auto-retry with exponential backoff
└─ Fallback to hardcoded prompts
```

### 🛡️ Safety Checks

```
Input Validation:
├─ message length > 5000 chars? → truncate
├─ message is null? → use empty string
├─ session_id contains "/"? → sanitize
└─ special characters? → escape

Output Validation:
├─ response length > max_tokens? → truncate
├─ response contains API keys? → redact
├─ response is null? → use fallback
└─ response is HTML/script? → escape

Token Limits:
├─ Session total > 30,000 tokens? → warn
├─ Session total > 100,000 tokens? → refuse
├─ Per-request > max_tokens limit? → error
└─ Rate limit > 30 req/min? → HTTP 429

Permission Checks:
├─ Can read session file? → check ownership
├─ Can write state? → check disk space
├─ Can delete old sessions? → whitelist dirs
└─ Can access vector DB? → connection test
```

## Performance & Optimization

### ⚡ Speed Optimization

```
1. Caching:
   ├─ SimpleCache (in-memory)
   ├─ Key: (session_id, message_hash)
   ├─ TTL: 24 hours
   ├─ Miss rate: ~40-50% (good!)
   └─ Hit saves: 100-500ms per request

2. Batching:
   ├─ Practical slots: max 2 asks
   ├─ Academic slots: all at once (1 LLM call)
   └─ Reduces round-trips

3. Early Exit:
   ├─ Greeting → no retrieval
   ├─ Noise → no retrieval
   ├─ Smalltalk → no retrieval
   └─ Save 500-1000ms per request

4. Vector Search:
   ├─ Top-K: 20 → 6/12/15 after filter
   ├─ Min similarity: 0.6
   ├─ HNSW index (fast)
   └─ < 100ms per search

5. LLM Optimization:
   ├─ Temperature: 0.2-0.3 (lower = faster)
   ├─ Max tokens: 4500-8000 (not unbounded)
   ├─ Prompt caching (future)
   └─ Batch multiple requests (future)
```

### 💰 Cost Optimization

```
1. Model Selection:
   ├─ Practical: claude-sonnet (cheaper, faster)
   ├─ Academic: gpt-5.1 (expensive, but thorough)
   ├─ Topic picker: claude-haiku (fastest, cheapest)
   └─ Fallback: when budget exceeded

2. Token Reduction:
   ├─ Reduce docs max: 6 → 4 saves 30%
   ├─ Reduce char per doc: 700 → 500 saves 20%
   ├─ Trim messages: keep last 12 only
   ├─ Skip internal_messages in prompt
   └─ Total: ~40% token savings

3. Smart Caching:
   ├─ Cache hit = $0 ✓
   ├─ Hit rate: 40-50% (typical)
   ├─ Saves per session: 50-200 requests
   └─ Cost per session: -40% ✓

4. Rate Limiting:
   ├─ Prevent spam (burst abuse)
   ├─ Reduce cost spikes
   ├─ Keep service quality
   └─ Impact: minimal on normal users

Typical Session Cost:
├─ Greeting: $0 (no LLM)
├─ Legal question: $0.01-0.05 (1-2 LLM calls)
├─ Follow-up: $0.005-0.02 (cache hit likely)
├─ Academic deep-dive: $0.10-0.30 (many calls)
└─ Average per session: $0.05-0.15 ✓
```
